# سند طراحی Silent Tunnel

تاریخ: ۲۰۲۶-۱۰-۰۴
وضعیت: تأییدشده بر اساس انتخاب‌های کاربر (معماری معکوس + فوروارد پورت، استتار TLS با SNI جعلی + رمز داخلی، پنل x-ui/3x-ui پشت تونل، بسته کامل بدون پنل وب)

## ۱. هدف و پیشینه

ساخت یک تونل اختصاصی «ایران → خارج» برای عبور از فیلترینگ، با جمع‌بندی بهترین تکنیک‌های چهار پروژه‌ی مرجع:

| مرجع | تکنیک اقتباس‌شده |
|---|---|
| RTT-ReverseTlsTunnel | تونل معکوس (خارج به ایران وصل می‌شود) + SNI جعلی + مالتی‌پورت |
| Hedioum-Pool-Tunnel | استخر اتصالات فیزیکی، رمز AEAD داخلی با کلید از توکن، توکن pairing یک‌خطی |
| BackPack | ری‌کانکت خودکار با backoff، decoy ضد پروب، پیکربندی تمیز |
| Easy-Mesh | (نقد) معماری مش L3 برای نسخه‌های آینده |

نام‌گذاری: **Silent Tunnel** (به انتخاب کاربر).

## ۲. معماری

```
کاربر ──▶ سرور ایران (hub) ═══ تونل ═══▶ سرور خارج (node) ──▶ x-ui / 3x-ui
          پورت‌های فوروارد‌شده      TLS+SNI جعلی             سرویس روی 127.0.0.1
```

- **hub (ایران):** یک پورت TLS گوش می‌دهد (پیش‌فرض 443) که node به آن وصل می‌شود؛ به‌علاوه پورت‌های عمومی که کاربر به آن‌ها وصل می‌شود و ترافیک را از داخل تونل به node می‌فرستد.
- **node (خارج):** خودش به hub زنگ می‌زند (پس هیچ پورت ورودی روی خارج لازم نیست)، N اتصال TLS (پیش‌فرض 3) را در استخر سالم نگه می‌دارد و هر استریم جدید را به `127.0.0.1:<پورت>` محلی وصل می‌کند.
- جهت اتصال: node → hub. از دید DPI بین‌المللی، یک کلاینت TLS معمولی با SNI یک دامنه‌ی معتبر است.

## ۳. پروتکل روی سیم (لایه‌ها)

1. **TLS 1.3** — گواهی خودامضایی که hub در `setup-hub` می‌سازد (CN/SAN = SNI انتخابی). node با `ServerName=SNI` وصل می‌شود و اثر انگشت SHA-256 گواهی را که در توکن pairing است، pin می‌کند (بدون اتکا به CA).
2. **دست‌دادن داخلی (Auth)** — بلافاصله بعد از TLS:
   - node → hub: `magic "SLNT" | ver(1B)=1 | clientSalt(16B) | proof(32B+)`
   - proof = ChaCha20-Poly1305 با کلید `HKDF-SHA256(token, salt=clientSalt, info="silent/v1/auth")` و AAD شامل magic/ver/salt؛ متنِ رمز = timestamp(8B) + nonce تصادفی(24B). پنجره‌ی زمان ±120 ثانیه (ضد ری‌پلی).
   - hub در صورت نامعتبر بودن: تا ۵ ثانیه صبر، بعد جواب **decoy** `HTTP/1.1 404 Not Found` شبیه nginx و بستن.
   - hub → node: `serverSalt(16B) | ack(32B+)` — رمزشده با کلید جهت hub→node شامل timestamp هاب و echo همان nonce؛ node هم صحتش را تأیید می‌کند (احراز دوطرفه).
3. **رمز داخلی ماندگار** — از این لحظه کل اتصال در قاب‌های AEAD می‌رود:
   - `keyC2S, keyS2C = HKDF-SHA256(token, salt=clientSalt‖serverSalt, info="silent/v1/data", 64B)` → دو کلید 32 بایتی.
   - قاب: `len(3B BE) | ciphertext+tag(16B)`؛ nonce = 4 بایت صفر + شمارنده‌ی 8 بایتی یک‌طرفه.
   - نتیجه: توکن هرگز روی سیم نمی‌رود؛ محتوا حتی با لو رفتن گواهی TLS هم رمز است.
4. **مالتی‌پلکس** — `xtaci/smux` روی اتصال رمزشده: node = smux.Client، hub = smux.Server. KeepAlive هر 10s، تایم‌اوت 30s، بافر استریم 4MB (مناسب لینک پرتأخیر).
5. **پروتکل استریم** — اولین نوشته‌ی hub روی هر استریم: `remotePort(2B BE)`؛ node به `bindAddress:remotePort` وصل می‌شود و بقیه‌ی عمر استریم، رله‌ی دودویی است.

## ۴. مپینگ پورت

- منبع حقیقت: کانفیگ hub. حالت پیش‌فرض **same-port** (پورت کاربر در ایران = پورت سرویس در خارج، مثل multiport در RTT).
- حالت صریح: `maps = [[listenPort, remotePort], ...]` در کانفیگ؛ hub پورت ریموت را در هدر استریم می‌فرستد.
- پیش‌فرض `setup-hub` برای سناریوی x-ui: پورت‌هایی که کاربر می‌پرسد، هم‌نام به خارج می‌روند.

## ۵. توکن Pairing

- خروجی `setup-hub`: رشته‌ی `st1_<base64url(JSON)>` شامل: `{v, host, port, sni, maps, key(base64 32B), fp(hex SHA-256 گواهی)}`.
- `setup-node --token st1_...` فقط همین را می‌خواهد — مثل آنبوردینگ هدیوم.
- هر کس توکن را دارد می‌تواند از تونل استفاده کند؛ مثل کلید SSH — مستند می‌شود.

## ۶. پایداری

- node: حلقه‌ی استخر با N کارگر؛ هر کارگر بعد از قطع، با backoff نمایی 1s→30s + جیتر وصل می‌شود.
- انتخاب اتصال برای استریم جدید: round-robin روی اتصالات سالم؛ اگر هیچ‌کدام سالم نبود، انتظار تا 10 ثانیه.
- hub: پذیرش چند سشن برای یک توکن (سقف 16)؛ شمارش بایت/استریم برای status.
- نصب روی سرور: systemd با `Restart=always` (واچ‌داگ خودکار، الگوی RTT/BackPack).

## ۷. CLI، TUI و فایل‌ها

**TUI تعاملی (خواسته‌ی کاربر):** اجرای `silent` بدون آرگومان، منوی گزینه‌ای تعاملی باز می‌کند (انتخاب با کلیدهای جهت‌دار یا عدد) — همه‌ی عملیات بدون حفظ کردن دستور:

```
  ┌──────────────────────────────────────────┐
  │  Silent Tunnel v1.0                      │
  └──────────────────────────────────────────┘
  ▸ ۱) راه‌اندازی این سرور به‌عنوان هاب (ایران)
    ۲) راه‌اندازی این سرور به‌عنوان نود (خارج)
    ۳) اجرای تونل (بر اساس کانفیگ موجود)
    ۴) نصب سرویس systemd (اجرای خودکار پس از ریبوت)
    ۵) وضعیت زنده
    ۶) تست سلامت (doctor)
    ۷) نمایش توکن Pairing
    ۸) حذف کامل (uninstall)
    ۰) خروج
```

- هر گزینه یا ویزارد سؤال‌به‌سؤال اجرا می‌کند (پورت، SNI، پورت‌های فوروارد — با پیش‌فرض منطقی و Enter) یا مستقیم عملیات را انجام می‌دهد.
- پیاده‌سازی با `AlecAivazis/survey/v2` (همان کتابخانه‌ی هدیوم) + `fatih/color`.
- اگر stdin تی‌وای نباشد (اسکریپت/اتوماسیون)، منو باز نمی‌شود و خطا راهنمای دستور مستقیم را می‌دهد.

**دستورهای مستقیم (برای اتوماسیون):**

| دستور | محل اجرا | کار |
|---|---|---|
| `silent setup-hub --port 443 --sni d --maps 2087,44301 [--host IP]` | ایران | ساخت کانفیگ/گواهی + چاپ توکن |
| `silent setup-node --token st1_... [--pool 3]` | خارج | ذخیره‌ی کانفیگ از توکن |
| `silent hub` / `silent node` | — | اجرای دیمن |
| `silent status` | هر دو | وضعیت زنده از فایل وضعیت (سشن/استریم/بایت) |
| `silent doctor` | هر دو | چک کانفیگ، گواهی، دسترس‌پذیری host:port |
| `silent install` | سرور | ساخت سرویس systemd |
| `silent token` | ایران | نمایش دوباره‌ی توکن pairing |

- کانفیگ: `/etc/silent/hub.json` و `/etc/silent/node.json` (در ویندوز: کنار باینری).
- فایل وضعیت: هر 5 ثانیه JSON → `/var/lib/silent/status.json` (ویندوز: `%LOCALAPPDATA%\silent\status.json`).

## ۸. محدوده‌ی نسخه‌ی ۱

- فقط TCP (پنل/پروکسی‌های V2Ray TCP هستند). UDP، TUN، استخر چند-استتار و L3 → نقشه‌ی راه بعدی.
- یک hub، چند node مجاز (هر توکن = یک node؛ چند توکن قابل ساخت).
- زبان: Go 1.27؛ وابستگی بیرونی: فقط `xtaci/smux` و `x/crypto`.

## ۹. تست

- Unit: قاب AEAD (roundtrip با net.Pipe، خرابی قاب دستکاری‌شده)، توکن (roundtrip و رد garbage)، مپینگ.
- E2E در همان پروسه: hub و node درجا بالا می‌آیند؛ یک سرور HTTP ساختگی روی سمت node؛ اتصال به پورت فورواردشده‌ی hub باید پاسخ HTTP برگرداند؛ احراز ناموفق باید decoy بدهد.
- بعد از آن: تست دستی دو-سروره توسط کاربر با README.
